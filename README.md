# Интеллектуальное планирование маршрутов выездных инженеров

Репозиторий прототипа для распределения заявок между инженерами и построения
маршрутов с временными окнами, квалификациями и транспортными ограничениями.

Проект включает автономный Python-пакет оптимизации, Go REST API с PostgreSQL и
операторский web-интерфейс.

## Структура

```text
.
├── data/
│   ├── raw/                 # локальные исходные CSV и архив; не коммитятся
│   ├── reference/           # нормативы длительности работ
│   └── README.md            # состав и правила использования данных
├── docs/
│   ├── source/              # исходные документы организаторов
│   └── data-audit.md        # результаты первичного аудита
├── backend/                 # Go API, PostgreSQL, миграции и Swagger
├── frontend/                # React + TypeScript web-панель диспетчера
├── solver/                  # модели, алгоритмы, тесты и ноутбуки
├── docker-compose.yml       # PostgreSQL + backend + solver + frontend
└── README.md
```

Описание исходных файлов и важные ограничения находятся в
[`data/README.md`](data/README.md), результаты проверки — в
[`docs/data-audit.md`](docs/data-audit.md).

Готовая презентация по официальному шаблону находится в
[`presentation/routecraft_lct2026.pptx`](presentation/routecraft_lct2026.pptx).
Уточнения из чата организаторов и их реализация сведены в
[`docs/chat-requirements.md`](docs/chat-requirements.md).

## Важно

- Файлы `control_assignment.csv` предназначены только для последующего сравнения
  результата. Передавать готовые назначения бригад в оптимизатор нельзя.
- Исходные CSV хранятся без преобразований: кодировка `cp1251`, разделитель `;`.
- Время дороги из Excel-норматива нельзя прибавлять ко времени обслуживания, если
  время пути уже берётся из маршрутной матрицы.

## Запуск приложения

При установленном Docker:

```bash
docker compose up --build
```

Web-интерфейс откроется на <http://localhost:8080>, Swagger — на
<http://localhost:8080/swagger/index.html>. Подробности находятся в
[`backend/README.md`](backend/README.md).

В интерфейсе точки ставятся кликом по карте. По умолчанию compose использует
публичный OSRM для дорожной матрицы и геометрии; для автономной работы укажите
свой `OSRM_BASE_URL`.

После расчёта интерфейс показывает сравнение с обязательным baseline
«входной порядок → первый допустимый инженер». Для каждой остановки доступно
короткое объяснение назначения; длинная техническая трассировка намеренно не
выводится. Время поездки учитывает тип транспорта исполнителя.
Название алгоритма, лимит времени, seed и runtime в рабочем интерфейсе скрыты:
они остаются серверными параметрами и данными аудита.

## Проверка перед сдачей

Полный локальный набор тестов (Go, Python, React, TypeScript и production build):

```bash
./scripts/verify.sh
```

После `docker compose up --build` развёрнутый стенд должен пройти smoke-тест:

```bash
./scripts/smoke-test.sh
```

Он проверяет healthcheck и подключение к БД, выдачу React-приложения, Swagger,
а также полный цикл создания, чтения и удаления тестовой заявки. Массовая
очистка защищена отдельными backend-тестами и в smoke-тесте не вызывается, чтобы
не удалить пользовательские данные.
