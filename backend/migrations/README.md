# Схема PostgreSQL

`000001_initial_schema.up.sql` создаёт минимальную схему для рабочего MVP.

| Таблица | Что хранит |
|---|---|
| `requests` | Входящие заявки, координаты, окно, норматив, требуемые ресурсы и жизненный статус |
| `brigades` | Бригады, график `2/2`/`5/2`, границы смены, стартовая точка, транспорт и доступность |
| `brigade_skills` | Нормализованный набор навыков бригады |
| `plans` | Запуск solver, параметры воспроизводимости и полный JSON-снимок результата |
| `plan_routes` | Итоги маршрута каждой бригады и GeoJSON-геометрия |
| `plan_stops` | Упорядоченные остановки с расписанием и метриками переезда |
| `plan_unassigned` | Неназначенные заявки и машинно-читаемые причины |
| `replan_events` | События оперативного перепланирования и ссылка на новый план |

Время хранится в PostgreSQL `time`, абсолютные даты событий — в `timestamptz`,
координаты — в WGS84 (`latitude/longitude`). Полный `solution` в `plans` нужен
для быстрого чтения API, а нормализованные дочерние таблицы — для аналитики.

Backend применяет все `*.up.sql` по имени при старте и записывает версии в
`schema_migrations`. Откат оставлен отдельным SQL и выполняется осознанно вручную.
Миграция `000002_brigade_work_schedule` добавляет график бригады и безопасно
проставляет существующим строкам значение `2/2`.
