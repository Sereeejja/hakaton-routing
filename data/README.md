# Данные проекта

## Раскладка файлов

```text
data/
├── raw/                            # игнорируется Git
│   ├── archive/
│   │   └── original_dataset.zip    # исходный архив организаторов
│   ├── east/
│   │   ├── jobs.csv
│   │   └── control_assignment.csv
│   ├── south_east/
│   │   ├── jobs.csv
│   │   └── control_assignment.csv
│   └── south_center/
│       ├── jobs.csv
│       └── control_assignment.csv
└── reference/
    └── work_duration_norms.xlsx
```

`raw/` уже исключён из Git правилом в корневом `.gitignore`. Это сохраняет
полученные от организаторов адресные данные локально и не добавляет их в pull
request. После клонирования репозитория пакет данных нужно получить отдельно и
разложить по схеме выше.

## Назначение наборов

- `jobs.csv` — обезличенные входные заявки для алгоритмов.
- `control_assignment.csv` — историческое/контрольное распределение для внешнего
  сравнения. Колонки статуса и бригады запрещено использовать при построении
  решения.
- `work_duration_norms.xlsx` — исходные нормативы дороги, технических работ и
  оформления документов.
- `original_dataset.zip` — неизменённый пакет организаторов. Все шесть извлечённых
  CSV побайтово совпадают с файлами внутри архива.

## Технический формат CSV

- кодировка: `cp1251`;
- разделитель: `;`;
- окончания строк: CRLF;
- в конце каждого `jobs.csv`: две пустые строки и отдельная строка с адресом
  офиса;
- строкой заявки считается строка с числовым значением поля `Заявка`.

Исходные CSV намеренно не перекодированы и не очищены. Нормализация должна быть
воспроизводимым отдельным шагом загрузчика, а не ручным изменением файлов.
